HOME HUNTERS — INTERACTIVE SYSTEM BLUEPRINT
نسخة الموقع التفاعلي المقترح لشرح رحلة العميل والمشروع والإدارات والتقارير والذكاء الاصطناعي
=============================================================================

1) محتويات الملفات
- index.html     الصفحة الرئيسية للموقع
- styles.css     الشكل والألوان والتجاوب للموبايل
- data.js        محتوى الأقسام والرحلة والأرقام والأمثلة
- app.js         التنقل والبحث والمحاكاة التفاعلية
- assets/        أيقونة الموقع
- docs/          PDF المرجع الكامل للمتطلبات
- robots.txt     طلب عدم أرشفة الموقع من محركات البحث (ليس حماية أمنية)

2) تجربة الموقع قبل الرفع
- فك ضغط ZIP بالكامل في فولدر واحد.
- افتح index.html باستخدام Chrome أو Edge.
- ابدأ من الرئيسية، ثم رحلة المشروع أو Case Study.
- أو استخدم ملف Home_Hunters_Standalone_Preview.html المنفصل إن تفضّل فتح ملف واحد.

3) رفع الموقع على السيرفر — cPanel / Apache / Nginx / Static Hosting
- افتح ملفات موقعك، مثل public_html في cPanel، أو مجلد الموقع في الاستضافة.
- ارفع محتويات ZIP كلها: index.html + ملفات JavaScript + CSS + مجلدي assets وdocs.
- حافظ على ترتيب الملفات نفسه؛ لا ترفع index.html وحده.
- بعد الرفع افتح: https://your-domain.example/
- افحص الرئيسية، رحلة المشروع، Case Study، المدفوعات والـAI، وافتح ملف المرجع PDF.
- يشتغل تحت مسار فرعي أيضًا، مثل: https://your-domain.example/home-hunters/
- لا يحتاج Node.js أو قاعدة بيانات أو أي API أو تثبيت حزم.

4) الأمان والخصوصية
- الموقع شرح تفاعلي للنظام المقترح، وليس نظام ERP جاهزًا أو متصلًا بالعملاء.
- كل الأسماء والأرقام التوضيحية وهمية؛ لا تضع بيانات أو كلمات مرور حقيقية في ملفات JS.
- لأن الملفات ثابتة، أي شخص يملك رابط موقع عام يستطيع قراءة محتواها والمستند PDF.
- إذا كان المحتوى مخصصًا للعميل فقط، فعّل حماية بكلمة مرور من إعدادات السيرفر
  (cPanel Directory Privacy أو Nginx/Apache Basic Auth أو بوابة هوية موثوقة).
- robots.txt وnoindex يساعدان على عدم الفهرسة، لكن لا يمنعان الدخول.
- استخدم HTTPS بشهادة SSL عند النشر.
- أي بوابة عميل فعلية، أو تسجيل دخول، أو مدفوعات، أو AI متصل، يحتاج Backend
  وقاعدة بيانات وصلاحيات وتكاملات منفصلة؛ غير موجودة في هذا العرض.

5) تعديلات المحتوى
- بيانات الأقسام والـJourney والتقارير والموافقات يمكن تعديلها في data.js.
- السيناريو التفاعلي موجود في app.js، والمظهر في styles.css.
- يمكن تغيير PDF المرجعي في docs/ مع الإبقاء على الاسم نفسه.

6) افتراضات وملاحظات مهمة
- التسجيل يتم من Sales أو Marketing، وليس العميل.
- العميل لا يملك Login على ERP؛ فقط روابط Signing وPayment وشهادة Handover عند الحاجة.
- القاعدة التجارية: B2C عبر SMS، B2B عبر Email، دون WhatsApp خارجي.
- كل صفحة من Quotation وContract تتطلب توقيعًا وفق التصور، عبر رابط واحد.
- لا يُنشأ Project قبل تأكيد الدفعة المطلوبة والتوقيعات.
- AI Call-to-Ticket للصيانة وخدمة العملاء فقط؛ CEO Assistant للقراءة فقط.
- المشروع Smart Home/ELV لا يُفترض دمجهما قبل موافقة العميل على قاعدة التصنيف.
- إلغاء Formal Performance Evaluation من HR مقترح ويحتاج اعتمادًا مكتوبًا.
- العقد والأرقام المالية في Case Study توضيحية وليست عرض سعر أو نتائج فعلية.
- يجب اعتماد النطاق والقواعد والتكاملات من Home Hunters قبل التطوير النهائي.
